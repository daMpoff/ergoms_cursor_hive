# Product behavior

CursorHive coordinates two equal workers through a local shared board. One worker seeds useful parallel tasks; either can integrate the result. There is no permanent model manager.

The product is independent of ERGO MS. A saved Git working tree, including admitted dirty and untracked text files, forms the baseline. Worker copies have private Git administration. Publications freeze bytes and imports reject incompatible changes.

Version 0.1 exports results into private run storage. It never automatically applies changes to the original project. Workspaces are retained for recovery. Missing or unqualified Cursor capabilities must fail explicitly; a fake demonstration is never labelled a real Cursor result.

Start, status, update, stop and recovery work through CLI and MCP. The supervisor survives controller/MCP disconnection. Workers cannot launch nested runs. Exact inheritance of a current IDE conversation is not promised.

Checks use an explicit argv profile against a separate snapshot. Model assertions do not establish readiness. An exported result still needs relocation/setup checks in the original environment.
